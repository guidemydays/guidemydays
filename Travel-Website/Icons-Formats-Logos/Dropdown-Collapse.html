Dropdown / Collapse

Picker (select-style dropdown) and disclosure (expand/collapse) standard — started 2026-08-26, rules being dictated live.

This doc is under active authoring with the owner. The structure below is a skeleton — sections get filled in as specific failing examples and their fixes are confirmed. Do not treat an empty section as "no rule exists"; it means the rule hasn't been dictated yet.

Scope

Two related but distinct control families on this site:

  • Dropdown / picker — a <select> or select-styled control the reader opens to choose one value from a list (e.g. "Choose your passport", "Choose a currency", region/country pickers).
  • Collapse / disclosure — a section that expands and contracts in place (accordions, "show more", day blocks, filter panels). Internally called "disclosure" elsewhere on the site (disc-btn, Formatting.html Active/Selected rows) — this doc uses "collapse" per the owner's own naming and should be read as the same family.

Guide pages are OUT OF SCOPE for this doc (owner rule 2026-08-26). Guides run under their own separate formatting rules end to end — guide-style.css, Guide Structure.html, Stops Structure.html, and the rest of the guide-specific doc set — never this one. A dropdown, picker, or collapsible block that appears INSIDE a guide (a currency-converter pill, a day-block disclosure, a hotel-tier picker) is governed there, not by anything below. This is a standing convention, not particular to dropdowns: every non-guide reference/formatting doc in this folder should carry the same notice, because "the site's rule" and "the guide's rule" are two different things and a doc that doesn't say so gets misapplied to guides by whoever reads it next.

The rule

Background — white is approved

White (var(--surface) / #ffffff light, the dark-mode surface token in dark) is the approved rest-state background for a dropdown / picker control (owner rule 2026-08-26). This resolves the tension noted under item 3 above: Selection Pills (selection-pills-badges-pills-to-badge-dots.html § 2) deliberately rejected a white rest state in favour of a pale tint — but that decision governs the Selection Pill / Badge / Pill-to-Badge family specifically, and does not carry over to the dropdown/picker family this doc covers. A picker going white is not the drift; it is this family's own approved look.

Hover — reuses the pills' four approved treatments, not a new one

A dropdown/picker's hover state uses the same four approved hovers as Selection Pills (owner rule 2026-08-26) — copied from selection-pills-badges-pills-to-badge-dots.html § 2.2–2.6, not reinvented here:

HoverMechanism
Darkenfilter: brightness(.82) on hover — tint deepens toward the solid ink. No saturate() boost.
Liftcolour unchanged, translateY(-2px) + a tinted shadow raises the control
Presshover dims (brightness(.94)), :active pushes the control down 1px with an inset shadow
Glowan ambient halo (box-shadow ring + blur) instead of a directional shadow

Which of the four applies to a given control is still TBD per control, exactly as it is for pills — not every control gets all four (on Selection Pills, small size only ever gets Darken or Press).
