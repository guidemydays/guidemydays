Brain / Reference / Formatting

These are the only pills, badges & dots approved to use on the site — AND HOVER

Rules

1
Guides are exempted — this doc never governs a guide page. A guide page (Travel-Website/guides/{city_slug}.html) and its Read-About/stops-map pair run their own separate rule set end to end — assets/guide-style.css, Guide Structure.html, Stops Structure.html, and the rest of Brain/CORE RULES/. A pill, badge, or dot that happens to appear inside a guide is governed by the guide's own doc set, never by this one.
2
No two pills in the same row/group share a color. Every sibling in one filter/legend/badge row is a different color, no exceptions — two different meanings reading as the same pill is drift, full stop. If a row is running out of distinct colors, that's a signal to re-check the grouping, never a reason to repeat one.
3
An icon-bearing pill needs more vertical room than the plain-text reference — use the shared has-icon modifier (padding:7px 14px), never a page-local override. web-travel-style.css's --fam-pad (4px 9px) is sized for text alone; an icon taller than the text line reads squished at that padding. has-icon isn't an arbitrary bump — measured live, the plain reference renders 130×22px (a 5.91:1 width:height ratio) and the has-icon version renders 188×30px (6.32:1) on the same "Very expensive" label — nearly the same proportion, just scaled up for the icon, not a different shape. Every pill in the same group takes the size of its tallest member — but "same group" means pills that share one purpose (e.g. the Cheap→Very-expensive cost-tier scale), not just visual adjacency in a row. A standalone control with a different job (an "All"/reset pill, say) sitting next to that group stays its own size even if it never carries an icon itself.
4
No pill ever defaults to an uncontrolled white — and "every pill in the group shares one color" is the Selection Pill exception, not a default. Corrected 2026-08-31: literal white is no longer banned outright — nt-white (#ffffff, ink #1a1a1a) is now an owner-approved Family 3 tone, § below. What's still banned is white by accident — an unstyled, uncontrolled pill that happens to render white because nothing else was set. A pill whose members carry distinct meanings (different regions, categories, statuses) needs a real .cp-*/.sb-* fill on every member — a colored dot icon next to plain uncontrolled white is not colored, it's undressed. Where a genuinely neutral tone is needed (an "All" pill, or a pill that truly carries no category meaning), use Family 3 — Neutral (.nt-*, eight tones White→Brown, § below) — deliberately, by name, never as an unstyled fallback; nt-cream (var(--warm)) is still the default tone when no more specific one is picked, nt-white is a deliberate pick like any other named tone, not a new default. An "All"/reset pill is the one exception to that default: it takes the deep end of that same White→Brown scale (nt-brown), never nt-cream or lighter — it should read as the darker pill next to the group it resets, not the same weight or lighter. "Every pill shares one color" is only correct for a true Selection Pill — options that are genuinely interchangeable except for which one is picked (a month, a preset) — never for a group whose members mean different things. Filter-selection controls (index.html's Help Me Choose, .fnd-ctl — a dropdown/select styled as a pill: "Flexible," "No preference," an emoji icon, white/cream at rest) are a different component category, not a Badge/Pill-to-Badge/Selection-Pill, and can vary outside this format — they're form inputs wearing the site's search-bar skin, not category badges, so white-at-rest and one uniform look across all of them is correct there, not a violation of this rule.
5
One pill group, one color family — .cp-*, .sb-*, and .nt-* never mix within the same group. If a group's natural color needs a shade the current family lacks (there is no sb-purple, for instance), the fix is to pick a different color that family does have, or move every member of that group onto another family together — never leave one member on .cp-* and its siblings on .sb-* or .nt-*. Family choice is a per-group decision, made once, applied to every member.
6
Hover is always one of the 4 approved variants — hov-darken, hov-lift, hov-press, or hov-glow (§4 above) — never a hand-rolled effect. All four derive their color from the pill's own family (var(--sp-rgb)/var(--sp-ink)), so a correctly-implemented hover can never introduce a color the pill doesn't already carry — that includes terracotta: terracotta is retired from pill hover sitewide (the one exception is .sibling-pill, which is not part of this doc's three components) and never appears on a hover derived from scratch. A page-local box-shadow glow, a hardcoded brightness tint, or any hover that doesn't map to one of the four is drift, however deliberate it looks.
7
Every pill/badge's text is centered both horizontally and vertically — never left-, right-, top-, or bottom-anchored inside its own box. align-items:center alone is not enough: an inline-flex box with no justify-content:center defaults to flex-start, so the moment the box is stretched wider than its text (a grid cell sized to 1fr, a shared min-width equalization pass), the label drifts to the left edge and only looks centered by accident when the box happens to hug the text exactly. Caught live on .selection-pill itself (owner: "these are not even centered") — the shared base rule was missing justify-content:center, silently left-aligning every stretched instance sitewide, from a plain hover fix like this one to a full month-grid migration. Both properties, every time: align-items:center AND justify-content:center.
8
Pills that are the same control — siblings in one filter row, tab strip, or legend — share ONE width: the widest label's own natural width, not each pill sized to just its own text. CSS Grid's 1fr auto-columns on an intrinsically-sized track does NOT equalize to the widest item in practice (verified empirically, not a working trick) — each column still sizes to its own content, so measuring the widest sibling's rendered width in JS (getBoundingClientRect) and setting that width on every member of the group is the reliable fix. The one exception is a pill labeled "All" (or any reset/all-encompassing option): it is a different control from the group it sits beside (Rule 3's own-size carve-out above), so it is never stretched to the group's shared width — it wraps to its own content instead.

Family 3 — Neutral: same flat wash + ink mechanism as Calm Pastel, for pills/links that carry no category meaning at all

Lift Hover — rest, hover, and selected — added 2026-08-31

Researched, not guessed: Lift (transform:translateY(-3px); box-shadow:...) already matches how other design systems implement a hover-lift — a physical "rising" effect via transform + a deepening shadow (LogRocket, Atlassian Design's elevation model, Jake Lee's CSS animation tools all converge on this). No change to the mechanic itself. Selected is new here — owner rule 2026-08-31: no ring, anywhere. The .is-on outline ring below (§ "Selected state — every color, all at once") is superseded for these three states; the replacement is a filled background (the pill's own ink color) plus a checkmark — one of the standard non-ring conventions for indicating a chosen chip/pill (Setproduct, Smart Interface Design Patterns). Icon note: the checkmark below is a plain stroke placeholder, not yet sourced from the Site-Icons.html catalogue as Non-Negotiable 28 requires — swap in the catalogue's own check glyph (specimen 1265 is the closest match but is a full decorative circle-badge icon, too heavy for this inline use; a plain line-check specimen would need to be confirmed) before this ships anywhere.

Glow Hover — rest, hover, and selected — added 2026-08-31

Researched, not guessed: Glow (box-shadow:0 0 0 6px rgba(var(--sp-rgb),.18), 0 0 18px rgba(var(--sp-rgb),.35)) matches standard practice — a color-matched shadow built from two stacked layers (a tighter solid-edge ring, then a softer blur), spread used deliberately rather than avoided. No change to the mechanic itself. Selected uses the same filled-background + checkmark treatment as Darken and Lift — no ring.

Press Hover — all 3 states — added 2026-08-31

Researched, not guessed: Press active state corrected from brightness(.85) to brightness(.95) — same pattern as Darken: the old 15% drop read heavier than convention. Design-system practice (LogRocket, Figma, NN/g, GeeksforGeeks) points to a light brightness dip (~5%) paired with scale(.98) and an inset shadow to read as "pressing in," registering within 100–150ms. scale(.98) and the doc's existing .15s transition already matched; only the brightness value needed correcting. Hover-before-press (filter:brightness(.94)) is unchanged — already close to convention.

The ring — what it's actually for — added 2026-08-31

Researched, not guessed: across other design systems, the outline ring is a focus indicator — "you can activate this now via keyboard" — not a selected one. Focus is transient (fires on :focus-visible, keyboard nav only) and accessibility-critical; selected is a persistent condition, normally shown with a fill, colour, or icon change instead. The section below (§ "Selected state — every color, all at once") is this site's old .is-on ring — a focus-ring pattern applied to mean "selected," which is why it never quite matched either job cleanly. It's kept below for the record, not as the current approach; Darken/Lift/Glow/Press above all use the filled + checkmark treatment instead.

Selected state — every color, all at once — added 2026-08-28

Another option for the selected state above: the same .is-on ring — outline:3px solid currentColor; outline-offset:3px (thickened from 1.5px/1px, the original was too faint and too tight against the pill's own border to read as selected; the wider offset now reads as two distinct rings — the pill's own border, then a clear gap, then the ring) — shown across the full approved palette at once, so every color's selected look can be checked side by side instead of one at a time, all three families included.
