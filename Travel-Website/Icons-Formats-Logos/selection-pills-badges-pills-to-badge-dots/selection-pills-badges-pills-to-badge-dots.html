THIS DOC IS THE SINGLE SOURCE OF TRUTH FOR EVERY NUMBER IN THIS SYSTEM — read it BEFORE changing any font-size, padding, or shape here or in web-travel-style.css, never after. On 2026-08-24 a crib, working from the owner's live frustration that pages "still look unchanged," unilaterally unified .badge and .pill-badge to a single invented 11px/3px 8px — without opening this doc first. It shipped, the owner caught it from the live site ("no way this was the height i chose"), and the crib had to trace ~11 same-day commits by hand to reconstruct what had actually been agreed here. Owner: "if you dont have all the rules we talled about 100% right it is not point. the validator will enforce the wrong code." · "measure the one i approved and enforce. it is not like whatever."

The rule going forward: (1) open this doc and read it before touching a shared size/padding/shape value — never re-derive from what "reads smaller" on one page, never guess. (2) After shipping, verify the LIVE site with real getComputedStyle() reads on the actual deployed page — done by the assistant itself, directly, not delegated to a subagent and not assumed from having pushed. (3) A push is not "done" until curl'd CSS/asset bytes match the local file — CDN propagation lags the push by up to a minute or two; report status, not intent. (4) When more items need a colour than the 8 families provide, or a row would collide in colour with another row nearby, give it a genuinely different shape (oval .legend-key, neutral, not fam-*) instead of reusing a family colour for a second meaning.

The family formerly called Orange is now BROWN (owner rule 2026-08-24) — its ink drifted from a warm burnt-orange toward a neutral brown over several rounds of "make it more brown / less orange" tuning, and the display name was updated to match what the colour actually reads as. The CSS class stays fam-orange everywhere on the live site (class="pill-badge fam-orange", data-icon="dot-orange", the --fam-orange-* tokens) — renaming the class itself would be a separate, much larger site-wide sweep across every page that carries it, not done as part of this colour tuning pass. When you see "Brown" in this doc or in Formatting.html#sec-badges, it means this same family.

1 · Desktop Pill Format (toolbar / control strips, ≥601px)

Canonical spec for desktop pill/button strips. First reference implementation: Guides-Index toolbar (Trips · Stats · Compare cities · Trip Type · When to go · Language · Flight time · Continent · Trip Length · Country · Best of · Also Recommended). Applies to any horizontal control/filter strip on the desktop site.

Owner exception — Time Zones, 2026-08-17. The region + sort strips on time-zones/index.html do NOT follow this squared glued format — the owner found six short region labels reading as a row of boxes, with "All" a big empty square. Both strips instead take the desktop toolbar tab's pill: white ground, 999px radius, 8px 18px, gap:8px, rim ladder .30 rest → .55 hover → .85 active with warm #fdf4ed fill on the last two and terracotta ink on the selected pill. This is not drift and must never be "restored" to the squared strip — the deviation lives inside a min-width:601px media block, which the pill-rest-state check strips before scanning, so a validator run stays clean either way. The page's base .pill rule keeps the standard rest shape; only the media-query override differs.

1 · The strip

Every button in the strip is a peer in a single flex row. Buttons stretch to fill the row width, but not to equal widths — each starts at its intrinsic content width, then grows proportionally.

}

3 · Borders & spacing

Every button carries a full 1.5px border on all four sides, white interior. Adjacent buttons touch edge-to-edge — the visible divider between neighbors is two 1.5px borders side-by-side, rendering as one continuous 3px line. The outer perimeter of the whole strip stays a single 1.5px line.

Do not use margin-left:-1.5px or any negative-margin overlap — the legacy glue trick produced inconsistent borders when mixed with wrapped items, because a wrapper never inherited the overlap. Kill the overlap on every item, direct or wrapped, and let borders touch naturally. Do not set column-gap, add margin-right, or otherwise inject spacing — the spec says touch; the page background must not show through anywhere between adjacent buttons.

4 · Text color — two variants (per-strip, not per-button)

Variant A — GOLD, scope-locked to the Guides-Index toolbar only. color:#8a6c1a. Every other desktop pill strip on the site uses Variant B — do not extend gold to essentials/Best-Of/any in-page filter or nav strip.

Variant B — BLACK, used everywhere else (in-page filter rows, section-nav grids, tab strips). color:#3d3a32 — matches .days-jump-item, .lang-menu-item, .gtag, #country-select.

6 · Icons / emoji

Emoji in the label render as OS-colored characters on both variants — that's the accepted look. Don't wrap them in a span to force a color; the icon-color-vs-text-color contrast is intentional.

7 · What this replaces

The old margin-left:-1.5px overlap trick, the old border-radius:6px pill shape, and the old equal-width flex:1 1 0 stretch (now content-proportional flex:1 1 auto) — all killed on desktop only. Mobile pill format is unchanged and lives in mobile.css (Form A / Form B, § 10 below).

4 · Shape rules — the non-negotiables

Each rule states what the thing is. What it must never be sits in parentheses — an aside naming the drift, never the rule itself. A rule written as a list of bans tells a crib what to avoid and never what to build.

ONLY THE FORMATS SHOWN IN THIS DOC ARE APPROVED — every pill and badge shipped anywhere on the site is one of the exact shapes, families, sizes and states demonstrated in this file, built with the exact classes shown. This is a closed list, not inspiration: a page never invents a new radius, a new colour, a new size, or a new variant because it "looks close enough" or "reads better here." (If the format a page needs isn't already demonstrated below, that's a gap — flag it to Open Recommendations. It is never a reason to build one in-page.)
SAME CASE always; SIZE now deliberately differs — border, colour, radius, gap and ALL CAPS are the § 3 box, unchanged, for the badge and the pill-to-badge alike; a page never gives either its own value for those. Size is the one exception (owner rule 2026-08-24, reversing the 2026-08-18 "always the same size" rule): a pill-to-badge keeps a fixed 12px / 4px 9px (it's a clickable control, usually alone in its row); a badge uses font-size:inherit + em-based padding so it always matches the text it's labeling, never a fixed px that could read bigger or smaller than that text depending on the page. (Still not two DIFFERENT boxes in the old sense — the retired 13px / 500 at 6px 14px was a badge with its own unrelated hand-picked size; inherit is not a hand-picked size, it's "whatever the context already is." A page-local class hard-coding a badge to a fixed px — 12px at 2px 8px, as some page-local classes still carry — is still drift.)
The shape is a 4px rounded rectangle — border-radius: 4px (var(--fam-radius)), the one value for every badge and every pill-to-badge, light and dark, at every size. (NOT OVAL — 999px / 50%. NOT SQUARE — 0. Both have shipped, repeatedly, for months — 4px is the only approved radius, full stop.)
Minimum 10px between them — the same 10px vertically and horizontally (gap: var(--fam-gap), which sets both). A floor, not a fixed value: a strip may space them further apart where the layout wants it, but a wrapping strip never takes one value between columns and a different one between rows. Measured off the lounge-page legend row, which is the reference (it lived on lounges-us until the two regional pages merged into essentials/lounges/ on 2026-08-22). (Below 10px the two borders start reading as one merged hairline. The old 5px token and the 8px phone override on the retired lounges-us page are both under the floor.)
The fill is the family background — that colour is what carries the meaning. (Not white — var(--surface) / #fff flattens it to a bordered label saying nothing.)
The label is text — a badge or pill-to-badge carries words only. No decorative character, no icon character, inside the label itself. The eight family colour-circle dots () belong on jump-nav pills that identify a family at a glance, never inside a badge's own label. A badge reads SEARCH. (Never a dot icon plus SEARCH — the family is already carried by the bg + border + ink trio, so the icon is redundant and makes the badge noisy.)
The colour comes from an approved family — Vibrant (§ 6, the live default) or, where a crib is told to ship one, Enamel / Ink / Stamp (§ 5) — all of that family's values, light and dark, never mixed with another family's. (Not a new hex — a near-miss, as shipped on cruises and cards-atm, is drift. If none of the approved families fits, that's a gap for Open Recommendations, never a ninth family invented in-page.)
GREY IS RESERVED FOR "ALL" — owner rule 2026-08-24. Grey never labels a specific category on any page; it is only ever the "show everything / no filter applied" pill. The other seven families are a free choice per page — whichever crib builds a filter/legend row picks which family means what on THAT page — with one hard requirement below.
A PILL'S COLOUR MATCHES EVERY BADGE IT'S ANCHORED TO — owner rule 2026-08-24. If a filter pill is fam-red for "Pickpocket", every per-row badge/tag reading "Pickpocket" on that same page must ALSO be fam-red — not a different hardcoded hex that happens to look close, and not a different family picked independently for the content badges. The pill and the thing it filters/labels are the same category and must be the same class. This is the single most common drift found in the 2026-08-24 audit: legend pill and content badge for the same category built by different passes, in different colours, on the same page.
ALL PILLS IN THE SAME ROW/GROUP ARE THE SAME SIZE — guaranteed by construction if every pill uses the shared --fam-fs/--fam-pad tokens (never a page-local override); this is the same rule as "the box in § 3 is the only copy of these numbers," restated because a page-local font-size/padding override on one filter pill and not its siblings is exactly the kind of drift the audit is checking for.
NO TWO PILLS IN THE SAME ROW SHARE A COLOUR — owner rule 2026-08-24. Every sibling in one filter/legend row is a DIFFERENT family, no exceptions, not just for grey. Found live on essentials/sims: "All" (grey) and "By region" (also grey) sitting in the same row — two different meanings reading as the same button. The test is mechanical: list every fam-X class in one .pills/filter row; if any value repeats, it is drift, full stop. (Grey gets its own extra rule above only because it additionally has a fixed MEANING — "all" — that the other seven don't; the no-duplicates rule applies to all eight regardless.)

5 · New approved families — Enamel · Ink · Stamp (2026-08-25)

Three additional colour options, approved by the owner 2026-08-25, mockup-reviewed and picked in a Claude Code session — additive, not a replacement. The 8 Vibrant families (§ 6) are unchanged and remain the default everywhere except Plan Essentials (see below). These three exist so a crib building a new badge/pill on a page that wants a different finish has real, specified options instead of inventing one. Picked over Stamp after a live side-by-side on the essentials/scams filter legend: Stamp's 8 tones are all earth/brown and read as near-identical across 7 different categories, where Enamel's gradient-plus-rim keeps every category distinct at a glance — the same reason Vibrant used 8 separate hues in the first place. 8 · Badge System — Complete Production Spec (merged 2026-08-25)

The full production badge system — every rule, color, and shape a badge or pill-to-badge follows anywhere on the site. This file is the single source of truth: no other pill/badge formatting doc exists.

The rectangle is always present — every badge renders as a full rectangle: colored background + matching border + family text. Never render a badge as bare colored text with no box. Even the shortest label ("GE") gets the full trio.

What is a badge

A badge is a small colored rectangle that classifies what a content item IS — static, non-interactive, never responds to hover or click. It has three parts locked together from the same color family: background, border, text. Badges appear in three shapes:

ShapeWhat it is
PillThe primary form — small rounded rectangle, single line. Example: GLOBAL ENTRY / CLEAR on Trusted-Traveler.
Inline tagA shorter pill sitting inline inside a paragraph. Example: GE KIOSK.
Card wrapperA full section header + tinted card. Example: the BOTH / HUBBY / WIFEY / SOLO cards on the Trips page.

When to use a badge (all four must be true)

  1. You are classifying what something IS — its type, status, or category.
  2. The same categories repeat across many content items (so color becomes scannable).
  3. Color carries distinct semantic meaning per category.
  4. The element is non-interactive (no click behavior). If it needs to be clickable, keep the badge colors for the rest state and layer a terracotta hover on top (this becomes a pill-to-badge, § 10) — both are correct together.

Badges without pills — the most common pattern

Badges are very often used alone, with no matching jump-nav pills. The badge classifies the card; that is the complete job. Jump-nav pills are an optional add-on, only needed when there are distinct sections a reader would want to jump to from the top of the page — e.g. a page with SEARCH / CHAIN / AGGREGATOR badges scattered under plain section headers ("HOTEL CHAINS", "RENTALS") needs no pills, because the section headers already separate the groups. Add jump-nav pills only when: (1) the page has distinct named sections, (2) the sections are long enough that a reader would need to jump rather than scroll, and (3) each section's badge family is the logical anchor. Example where pills ARE warranted: Digital-Nomad-Visas — EUROPE / AMERICAS / ASIA-PACIFIC are each long enough to justify a jump pill.

The dot-echo rule — a dot belongs inside a badge only when matching jump-nav pills-to-badge exist at the top of the same page and also carry the dot. The dot's job is to create a visual echo: the pill at the top shows Europe, the badge on the card shows EUROPE — the matching dot tells the reader "this card belongs to the section that pill jumps to." Without pills at the top the echo has nothing to connect to (the bg+border+text trio already communicates the family) and the dot is just noise. No pills at top → no dot in the badge. When a dot IS used, it is always the real catalogue icon (Site-Icons.html § Dots / data-icon="dot-*") — never an emoji typed in markup, never a CSS flat disc.

Rules

The badge label can never render bigger than the text it sits beside (owner correction 2026-08-24, re-emphasized 2026-08-25 — this supersedes any older "canonical 11px, reduce as a last resort" model). Badge and pill-to-badge stopped sharing one fixed size on 2026-08-24: a static row label was reading heavier than the row it labelled at the pill's own full size. The two roles now behave differently:
  • A static label (Pill / Inline tag / Card-wrapper header — anything that is NOT a clickable filter/tab) is .badge: font-size: min(1em, 12px), padding 3px 8px. It inherits from whatever text it sits beside — a 13px table row, a 16px card headline — capped at a 12px ceiling, so it can never read bigger than the text beside it. Never hard-code a fixed px on a badge — a number that "looks right" beside one piece of text becomes bigger than the text beside it the moment that class sits next to something smaller elsewhere.
  • A clickable control (a filter pill, a tab, a jump-nav button — a pill-to-badge) is .pill-badge: a fixed 12px / 4px 9px. It is usually the only thing in its row, so there is no surrounding text to match — a fixed size is correct for it, and only it.
  • Colors are absolute for both roles — no substitution, no approximation.
  • ALL CAPS is absolute for both roles — no exceptions, every page.
  • Within a page, every pill-to-badge in the same row/group is the same height — guaranteed by construction if every one uses the shared tokens rather than a page-local override. A badge has no equivalent "same height" rule.
  • Only font-size and padding differ by role. font-weight (700), letter-spacing (0.04em), UPPERCASE, border (1px solid), border-radius (4px), line-height (1), and the color trio stay locked and shared. Never override height directly — let it compute.

Width — stretch full-width or center as a compact cluster, decided by pill count, not a fixed threshold. What NOT to do

  • Icon on an h1 / intro-card heading. Every essentials/guide h1 is ALL CAPS, 700, #3d3a32, text only — no icon, no emoji, no flag before or after, ever. Same for intro-card headings.
  • Gold text on a non-Guides-Index pill. Gold is Type A only.
  • Bold ALL-CAPS dropdown items. Dropdown items are font-weight:400, regular case.
  • Pressed-down on a jump-nav pill. If you scroll away after clicking, the pill returns to rest — it never stays pressed.
  • Beige/cream background on a pill. Pills are always white at rest (see rule above).
  • Title Case on a badge. Badges are always ALL CAPS.
  • An arrow character appended to a button or pill label (Compare →). The button's shape is already the affordance; the external-link classes already draw an arrow via CSS. Hardcoding one doubles it, ignores CSS color, and breaks the shared standard. Never put →, ↗, or ► inside a button/pill label.

Implementation landmines (folded in from essentials-Page-Format.html, 2026-08-25)

Only 7 of the 8 families can be used on a PILL — ORANGE cannot. ORANGE's badge background is #fdf8f0 — identical to the canonical warm card token var(--warm). brain_check.check_no_beige_pill_button hard-fails that value on any selector matching pill|btn|button|chip|cta, because pills are white-or-family-tinted and warm tokens are for cards only. A pills-to-badge row may use YELLOW · GREEN · RED · BLUE · PURPLE · PINK · GREY at rest, never ORANGE — the ORANGE badge itself is still fine (badge selectors don't match the pill pattern). If a page has 6+ categories and reaches for ORANGE on a pill, re-map that category to GREY or GREEN instead and move the dot with it, so pill and badge stay the same family. Learned on First-Timer-Mistakes 2026-08-07, which hard-failed with .pill[data-filter="distance"] on ORANGE.
Detection rule for pills-to-badge — mandatory, not optional. If a page has a badge legend AND jump-nav or region/category pills, those pills MUST use badge family colors — assign one family per pill. Plain neutral styling (var(--surface)/var(--border)) is wrong on any page with a badge legend.
Form B mobile grid — a one-word label orphans its leading dot when the pill also carries a count badge. A pill in the 3-across mobile grid is only ~120px wide. When it carries a .pill-count badge, that reserves width first, and a single unbreakable word (Distances, Moderate) can no longer share the line with a leading dot/emoji — the dot wraps onto its own line, reading as a bare dot stacked above the word. Two-word labels hide the bug (they wrap after the first word, dot still attached). Fix: .pill-count { display: none !important; } inside @media (max-width: 600px) — desktop already hides the counts, so this also makes both breakpoints consistent. Shrinking the font instead does not reliably fix it; the badge is what's taking the space. Seen on First-Timer-Mistakes and Airport-Connection-Times, 2026-08-07.
A status badge inline in a wrapping flex header lands on a different line row to row — pin it. When a row header is display:flex; flex-wrap:wrap and ends with a badge pushed right by margin-left:auto, the badge stays inline on rows with a short title and wraps below on rows with a long one, so the header changes shape down the page. Force the break on every row instead of letting content decide: .row-header::after { content:""; flex-basis:100%; height:0; order:98; } plus .row-badge { order:99; flex:0 0 auto; margin-left:0; }. Don't put flex-basis:100% on the badge itself — that stretches its background across the full row width. Seen on Airport-Connection-Times, 2026-08-07.
Badge legend strips with unequal label lengths need min-width on the short ones. When a legend bar uses flex: 0 1 auto (natural/centered width, not full-stretch), a pill with a short label becomes a tiny sliver next to long ones — set an explicit min-width on every short-label pill inside the @media (min-width: 601px) block so the bar reads balanced.
A pill's .dot must stay visible at full color in every interactive state — background:revert or background:initial silently kill it. The dot's color comes from a class rule like .d-vf{background:#5eb833}; either value reverts it to transparent. The only permitted dot modification on hover is a white halo when the pill background goes to the terracotta gradient: box-shadow:0 0 0 2px rgba(255,255,255,.5). When the hover state is family-colored rather than gradient (e.g. a desktop legend strip), leave the dot completely unstyled in the hover rule. 
/* CORRECT */ .legend a.pill:hover .dot { box-shadow: none !important; }
/* WRONG   */ .legend a.pill:hover .dot { box-shadow: none !important; background: revert !important; }
