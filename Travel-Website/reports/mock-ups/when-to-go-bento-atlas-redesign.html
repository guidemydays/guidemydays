Climate Atlas — When to Go redesign concept. Proposed by trip-timing-audit 2026-08-31. Background and hero are unchanged.

What changes below the hero

1 — Month panorama strip: 12 season-coloured cards replace the flat button grid. Each card shows the month abbreviation, a season-code badge (W / Sp / Su / Au), and a representative average daily high. Spring cards are sage-green, summer are sky-blue, autumn are warm-brown, winter are slate-blue. The selected month gets a border ring. Immediate visual orientation — users see the seasonal shape of the year before touching a filter.

2 — Season preset tiles: the 4 presets grow from small pills into full editorial bento tiles with an icon badge, title, and one-line description. Each tile uses its season colour family. This makes the intent of each preset legible at a glance.

3 — Compact sticky filter panel: the controls move to a left sidebar (276px), freeing the right two-thirds for results. No more scrolling past all the controls before seeing any cities.

4 — Editorial result cards: each card has a 4px season-colour accent stripe, a season chip badge, a gradient temperature track (cool-blue → warm-amber → hot-red), and a rain pip. Compact enough for 3 across, no wasted space.

What is NOT changed

All content (city data, 240+ cities, temperature ranges, rainfall, guide links), the presets themselves (Beach / Mild spring / Winter escape / Cool autumn), the search input, the range sliders, the unit toggle, the compare feature, the sort order.

Implementation notes

The month panorama strip requires mapping each city's average high for the selected month — data already in climate.json. The season chip and stripe are derived from the same temperature threshold logic already used for data-preset. The filter panel layout is a grid column split — no structural JS change, only CSS. This IS a drastic redesign (replaces the layout model) and must not ship without owner decision.
